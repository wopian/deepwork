# Implementation status — natural mines milestone

## Implemented

- Windows-native Bun 1.4.0, Vue 3, Vite, PixiJS 8 and Tauri 2; Rust owns simulation and geology.
- Save version 6 / generator version 2. Older campaigns remain exportable and require an explicit fresh start. Reset requires `RESET`, archives before replacing the checkpoint, preserves frontend preferences, rotates campaign identity and rejects stale commands.
- 512-cell-wide terrain at 0.25 metres per cell, with 64×64 two-dimensional chunks. Each cell contains 1,000 quanta; one material unit contains 64,000. Sparse excavation/reveal masks and lossless bounded RLE saves preserve exact state.
- Seeded world-space veins, lenses, seams, branches, host inclusions and tapered margins. Deposits cross chunk boundaries independently of generation order. Authored finite reserve lenses intersect reachable drives before progression gates.
- Unrevealed geology remains neutral. Excavation exposes adjacent faces; automatic and directed surveys reveal local masks. Vein targeting reads revealed data only. Offline survey scheduling uses local masks, not global discovery flags.
- A 48-metre benched pit, continuous access ramp, commissioned lift, cleared tunnel portals and bounded extraction chambers with pillars. Worker/cargo routes follow floor clearance and lift portals. Valid work-face indexes and cached route inputs avoid scanning permanent walls and unchanged shafts every tick.
- Five finite station buffers and four transport segments, partial unloading, coalesced in-transit batches, upstream congestion, individual buffer upgrades, fair cargo preference and selected-segment freight boosts. Saves retain contents and travel progress.
- Finite reserve-feed warehouse prevents locked feed from blocking processing intake. Construction reserves protect shaft iron; fractional recovery preserves tiny tailings without duplication or endless reprocessing.
- History-dependent waste surface with shifting discharge pads, lateral expansion, bounded profile resolution, surface collision for particles and settlement after reclamation/disposal. Economic ledgers remain independent of visual compaction.
- Nearest-neighbour dirty chunk textures with viewport eviction; combined cargo/waste budgets and representative worker sprites. Extended terrain palette, mobile layout, camera controls, reduced motion, audio and display preferences remain supported.
- Authored headquarters starting equipment, including power for researched starter furnaces; recipe pause controls prevent unwanted use of shared feeds.
- Validated pacing and deposit content; deterministic bulk, precision and reclamation campaign strategies with scheduled, attentive and continuous modes. Reports include milestone windows, blockers, stalled-site inventories and generator versions. Incomplete campaigns return a failing exit status.

## Measured pacing

Continuous first-site construction checks include the first worker and actual iron output. Across one seed on all three geological profiles, medians are: conveyor 4:56, first iron 11:35, tactics 19:11, shaft 27:24, specialisation 48:35. All six early medians meet their windows; individual specialisation times range 43:02–51:26.

The isolated one-hour ability comparison produces 5.2–6.9% more credits with identical equipment. A matched three-seed scheduled comparison on the 275-point electrolysis revision reached headquarters 1.2–1.5% sooner with automatic tactical use. These results miss the 15–25% active-advantage target; they do not measure every possible manual production strategy. Updated-gate comparisons remain in progress.

A completed 30-minute native run with persistent waste history ended at 7,012.75 metres, 1,279,357 excavated cells and a 2,318,460-byte compact save. Its 171 samples include 38 desktop samples (median 58 FPS, frame P50 21 ms / P95 21.7 ms), 124 narrow-window samples (30 FPS, P50 31.6 ms / P95 42.2 ms), eight samples while another app tab hid the renderer and one warm-up sample. This is not an uninterrupted 30-minute desktop-60-FPS pass. Maximum sampled JavaScript heap was 213.6 MiB; native process working set was 178.2 MiB. Those measurements exclude some WebView/GPU memory.

The final package separately passes a two-minute fixed 1440-pixel desktop run at approximately 58 FPS with 250 worker sprites and 72 resident terrain chunks. Native portrait/touch checks verify buffer purchase, mineral preference, express selection, reload persistence and reset preserving settings. The automated app uses isolated temporary saves and a PATH without Bun/Node. Reloads produce Tauri fallback/old-callback warnings; no uncaught page errors occurred. The longer stress build predates the controls recipe, electrolysis research gate and extra transport labels. Its max-equipment fixture does not enable the controls recipe or buy the changed tier; physics/rendering are otherwise unchanged. Each later package has a separate native smoke check.

Finite copper caused several earlier campaign stalls. Precision controls now use an abstract 275 silicon : 25 copper : 1 gallium input ratio, preserving total recipe mass. Three previously stalled seeds (46, 55, 58) then reached headquarters within 42 days. The final full matrix and matching attentive/continuous comparisons remain in progress.

## Remaining acceptance work

- Full 4–6-week campaign tuning is not yet accepted. Early costs, construction reserves and trace proportions changed substantially; milestone medians and every-seed completion must be checked against the current matrix. Early continuous-play pacing and scheduled visits are different measurements: upgrades cannot be purchased during the offline interval.
- The automatic transport implementation is one active-front chain. Independently progressing branch networks and rerouting around congested branches remain beyond this milestone's current implementation.
- Filled active offline pipelines still advance with exact 20-Hz ticks. Empty/stationary intervals skip safely; fully aggregated active production remains future performance work.
- Current navigation uses authored bench/lift/drive geometry. It is not a general arbitrary portal graph or free-form mining planner.
- Pile equilibrium is a bounded profile solver with particle presentation. It does not simulate individual recoverable waste grains economically.
- Confirm sustained desktop frame times, retained memory, save size and fixed-tick throughput on the final build. Process working set and JavaScript heap do not include all WebView/GPU memory.
- Actual Android/iOS touch, FPS, suspend/resume and packaging require configured SDKs and real devices. Desktop touch emulation and portrait screenshots do not substitute for device evidence. macOS/Linux build verification and clean-machine Windows installation/uninstallation remain separate.

## Reproduce

Use a Windows shell. Never install dependencies from WSL.

```powershell
bun.exe install --frozen-lockfile
bun.exe run check:runtime
bun.exe test
bun.exe run build
cargo test --workspace --locked
cargo run -p mine-core --release --example balance -- depth 0
cargo run -p mine-core --release --example campaign -- 30 56 scheduled 8
cargo run -p mine-core --release --example campaign -- 30 56 attentive 8
bun.exe run tauri build --bundles nsis
bun.exe run test:native test-results 1800 release
```

The campaign arguments are seed count, days, mode, CPU worker count and optional starting seed (default 42). Worker count is bounded by available logical processors. They launch ordinary benchmark threads, not separate agents. Windows locks a running executable: finish the benchmark before a command that relinks the same example, or use `cargo test --workspace --lib --locked` for library regression while it runs.
